### 2. Voice Architecture Deep Dive

#### Audio Processing Pipeline
```
Browser → MediaRecorder API → WebM Audio → Base64 Encoding →
→ FastAPI → Whisper STT → Text → LLM Processing →
→ Response → ElevenLabs TTS → MP3 Audio → Browser Playback
```

#### Technical Decisions
1. **WebM Format**: Native browser support, good compression
2. **Base64 Transport**: JSON-compatible, firewall-friendly
3. **MP3 Output**: Universal playback support
4. **Async Throughout**: Non-blocking audio processing

#### Performance Characteristics
- **Recording**: Real-time, no lag
- **Transcription**: 1-2s for typical utterance
- **LLM Processing**: 2-5s depending on model
- **Synthesis**: 1-3s for average response
- **Total Pipeline**: 5-10s end-to-end

## Performance Analysis

### Current Metrics
- **API Response Time**: 200-500ms (without LLM)
- **LLM Response Time**: 2-15s (model dependent)
- **Memory Search**: 50-200ms
- **Voice Processing**: 5-10s total
- **Frontend Load**: <2s

### Bottlenecks Identified
1. **LLM Latency**: Largest time component
2. **Audio Transfer**: Base64 adds ~33% size
3. **Sequential Processing**: Could parallelize
4. **No Caching**: Repeated syntheses

### Optimization Opportunities
1. **Streaming LLM**: Start TTS before complete
2. **Binary WebSocket**: For audio transfer
3. **Response Caching**: For common phrases
4. **Parallel Processing**: STT + Memory search
